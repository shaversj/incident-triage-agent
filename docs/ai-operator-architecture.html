Operator loop

The loop is split into three authority lanes: observability evidence, model judgment, and deterministic control.

Current prototype: no production mutation

Authority split

LLM can do
Explain the provided evidence, choose one incident class, choose one next action, cite workflow-provided evidence IDs, and state caveats.
System owns
Evidence construction, response validation, provenance, mitigation catalog matching, approval state, simulated executor records, and scorecards.
LLM cannot do
Create runbooks, approve actions, execute mitigations, decide production mutation happened, or grade its own safety.

Current safety line

Approval-sensitive actions can be staged and approved, but execution remains simulated. The executor record stays explicit: 

{
  "status": "simulated_not_executed",
  "executed": false,
  "dry_run": true
}
